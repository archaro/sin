Plan for 0.7.0

This release should stabilise the in-memory itemstore (the on-disk format was
stabilised as v1 at 0.5.0).

Things to do:
  1. Opaque ITEM_t and explicit ITEMSTORE_t.
  2. Pin-counted execution lifetime and subtree-safe deletion.
  3. Separate topology and payload revisions.
  4. Encapsulated child-container invariants.
  5. Uniform ownership and mutation-result contracts.
  6. Itemstore-specific correctness and performance benchmarks.
  7. Removal of undefined behaviour from hashing.

The public contract should promise names, hierarchy, ordering, payload
semantics, pointer/handle lifetime, and mutation behaviour—not the byte layout
of the C structure.

The highest-value sequence is: benchmark first, fix lifetime safety, separate
cache epochs, encapsulate the representation, and only then choose the long-
term child storage.
  
...plus anything else which comes up.
